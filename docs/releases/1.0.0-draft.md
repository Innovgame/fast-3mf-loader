# fast-3mf-loader 1.0.0

These are the notes to publish with the `v1.0.0` tag. They describe the current public contract. Tagging `1.0.0` is a separate release step.

## Install

```bash
npm install fast-3mf-loader three
```

`three` is a required peer dependency at `>=0.170.0`. Import `Fast3MFLoader` and `fast3mfBuilder` from `fast-3mf-loader`. GitHub Packages publishes the same API as `@innovgame/fast-3mf-loader`.

`parse()` accepts one complete `ArrayBuffer`. `fast3mfBuilder()` returns a `THREE.Group`. `Model3MF` is an alias of `ParseResult`. The result fields are `rels`, optional `modelRels`, `model`, `printTicket`, and `texture`. This shape is frozen for 1.0.

## Supported in 1.0

- Archive unzip
- Root relationships (`_rels/.rels`)
- Additional model relationships (`.model.rels`) used to resolve texture targets
- Base mesh geometry
- Vertex colors
- Texture resources and texture groups
- Components, including Production `path` references to another model part
- A modern browser with `Worker` and `Blob`

The evidence is in [docs/support-matrix.md](../support-matrix.md). The verified browser and Three.js combinations are in [docs/browser-support.en.md](../browser-support.en.md).

## Not supported in 1.0

- Print tickets. The parser returns an empty `printTicket` and warns.
- Extension resources beyond the current fixtures, including end-to-end `pbmetallicdisplayproperties`
- A public chunked-input parsing API. SAX-style parsing is an internal implementation detail.
- Node.js as a library runtime. Node.js 22 is only for installing, testing, and building.

## Known limits

- Invalid `workerCount` values warn and use the default worker count: `min(hardwareConcurrency - 1, 15)`, or `4` when concurrency cannot be read.
- If workers cannot start, parsing fails with an error that names the `Worker` and `Blob` requirement.
- Missing archive parts, relationships, objects, components, and texture binaries throw an error that names the missing target.
- Unsupported builder resources warn instead of pretending to succeed.

## Benchmark evidence

Refresh the sample in [docs/benchmarking.md](../benchmarking.md) on the release machine before tagging `1.0.0`.

```bash
pnpm benchmark:release
```

That command fixes warmup `2`, measured runs `7`, and worker count `6` without a shell-specific environment assignment. It measures this library only. The sample is evidence for that machine. It is not a browser speed promise.
